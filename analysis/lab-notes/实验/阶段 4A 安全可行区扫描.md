# 阶段 4A · 安全可行区扫描

> **一句话**：PW 证明了 U=90 下连 P=0 都不安全（84.5% 越限），所以在优化 P 之前，
> 先用 **P≡0** 扫负载 U∈{50,60,70,80,90}，按冻结 §9 判定"哪些负载有可能满足 2% 预算"。
> **结果：U50 / U60 在假设 DEFF≤2.707 的条件下通过筛选；U70/U80 尚无法认证；U90 点估计未达标。
> 严格认证层：五档全部「尚无法认证」。**

---

## 1. 采集目的

### 1.1 要回答的问题

**在哪些负载 U 下，100 ms 约束还有可能被满足？**

4A **不测 P 的效应**：所有窗口 P≡0，先把"动作代价"这一项拿掉，
只看环境本身还剩多少时延余量。

### 1.2 判定口径

冻结的 §9 机械判定（详见 [[口径与术语#3. §9 冻结判定（4A / 4B 共用）]]）：

```
n = 可用窗（TLS 有值）      D_use = max(2.707, DEFF_obs)
p̂ = k/n                     hi = Wilson(p̂, n/ D_use)，单侧 95%，z=1.645
n<360 → 尚无法完成；k/n≥2% → 点估计未达标；hi<2% → 条件性通过；否则 → 尚无法认证
```

### 1.3 明确不回答的问题

- **[未答]** P>0 时还安不安全（这是 4B 的问题）；
- **[未答]** 熵增益能不能补偿时延（4A 没做 P，ΔR 恒为 0）；
- **[未答]** U80→U90 之间的拐点是速率-时延曲线拐点还是队列饱和（只有一个负载变量，没有中间档）。

## 2. 采集方式与范围

### 2.1 设计

| 项 | 值 |
|---|---|
| 负载 | **U ∈ {50, 60, 70, 80, 90}** |
| P | **恒 0** |
| 时段 | **每档 2 个时段**（a / b），共 10 个 session |
| 每 session | **185 窗**，窗长 32.5 s（settle 1.5 + 30 + 1） |
| 总量 | **1850 窗 ≈ 16.8 h** |
| 第 1 轮顺序 | U50a → U70a → U90a → U60a → U80a |
| 第 2 轮顺序 | U80b → U60b → U90b → U70b → U50b（倒序） |

**实际时间**：2026-10-17 11:14 → 19:47（第 1 轮），2026-10-18 11:04 → 19:37（第 2 轮）。
两轮起始钟点相隔约 24 h。每段 1.67 h。**没有第三时段**（设计不安排）。

### 2.2 采集链路

- 工控机 Node3 跑 `pw_round_runner.py --stage 4a`；采集器 `pw_collecting.py` **冻结未改**。
- 中间件分流；139 节点 iperf3 维持 U；Node4 提供独立利用率探针。
- **D1 身份闸门**：预检 → 人工确认 TLS/ICMP 目标 → `--confirm-targets` → 运行器才开跑。
- **不设临时补采**：某档可用窗不足 360 就记「尚无法完成」，不补。

## 3. 分析结果

### 3.1 结构闸门 —— **[实测] 全部通过**

| 项 | 要求 | 实际 |
|---|---|---|
| session 数 | 10 | **10** |
| 每时段窗数 | 185 | **185 / 185** |
| 每 U 合计 | 370 | **370 / 370** |
| 序列哈希 | `2caaa63c…bbcf2` | **10/10 匹配** |
| P 值 | 恒 0 | 全部 `p_requested = p_applied = 0.0` |
| `measurement_idx` | 连续 | **10/10 连续** |
| 探针可用率 | — | **10 段 × 4 探针全部 185/185**，`anomaly_flag` 0 例 |
| 相邻窗间隔 | — | **10/10 段全部恒定 2.5 s**，>60 s 空洞 **0** |
| `raw_packet_count` | 点击器在工作 | 全部 min 17–19、中位 20、**没有任何 <10 的窗** |

> 这一轮直接对症两类历史事故：**S5 的 `utilization` 整列归零**、**G3 的 4000/4000 空熵**。
> 本轮都没发生：entropy / util / TLS / ICMP 四个探针全部满格。

### 3.2 三层负载是否真的立住 —— **[实测]**

| U | `set_U`（命令） | `load_pct`（服务自报） | Node4 实测 util 中位 | uptime 回退 |
|---|---|---|---|---|
| 50 | 50 | 50.0 | **52.44% / 52.44%** | 0 |
| 60 | 60 | 60.0 | **62.92% / 62.92%** | 0 |
| 70 | 70 | 70.0 | **73.41% / 73.41%** | 0 |
| 80 | 80 | 80.0 | **83.90% / 83.90%** | 0 |
| 90 | 90 | 90.0 | **94.39% / 94.40%** | 0 |

三点值得记：

1. **两个时段的 Node4 实测利用率小数点后两位完全一致**（除 U90 差 0.01%）——
   这是"两时段确实是同一个负载水平"最有力的旁证，来自独立探针。
2. **实测值系统性高于命令值 2.4–4.4 个百分点**，且偏置随 U 单调增大。
   这是负载服务自身的口径偏置，不影响档位排序，也不影响 §9（§9 只用 `set_U` 分层）。
3. `process_alive` 有 **0.5–1.1% 的假 false**（183–185/185），是已知的 `/status` 噪声；
   `uptime_seconds` **10 个 session 零回退**，说明负载服务全程没重启。

### 3.3 §9 机械判定 —— **[实测]**

| U | n | k | 越限率 | 单侧上界 | §9 结论 |
|---|---|---|---|---|---|
| 50 | 370 | 0 | 0.000% | **1.9410%** | **在假设 DEFF≤2.707 的条件下通过筛选** |
| 60 | 370 | 0 | 0.000% | **1.9410%** | **在假设 DEFF≤2.707 的条件下通过筛选** |
| 70 | 370 | 1 | 0.270% | 2.4417% | **尚无法认证** |
| 80 | 370 | 5 | 1.351% | 4.1609% | **尚无法认证** |
| 90 | 370 | 269 | 72.703% | 78.4842% | **点估计未达标** |

**逐条读法：**

- **U50 / U60**：0 越限，`hi = 1.941% < 2%`。
  **余量只有 0.059 个百分点** —— 这是 k=0、n_eff>133 的必然结果，不是"远低于 2%"。
  少 4 个可用窗（n=366）仍是 1.96%、仍过；少到 n≈359 就落到 360 门槛之下。
- **U70**：点估计 0.270% 低于 2%，但 `hi=2.44%` 未过线 ⇒ **尚无法认证**。
  **`k=1` 在本轮预算下结构上不可能通过**（k=1 要 n_eff≈222 ⇒ 约 601 窗）。
  **不等于不安全。**
- **U80**：1.351% 的点估计同样低于 2%，`k=5` ⇒ `hi=4.16%` ⇒ **尚无法认证**。
- **U90**：72.70% ⇒ 在用到 Wilson 之前就结案。

**方向一致性（附加检查）—— 五档全部通过：**

| U | 时段 a | 时段 b | 两侧都 <2% |
|---|---|---|---|
| 50 | 0/185 | 0/185 | ✓ |
| 60 | 0/185 | 0/185 | ✓ |
| 70 | 0/185 | 1/185（0.541%） | ✓ |
| 80 | 2/185（1.081%） | 3/185（1.622%） | ✓ |
| 90 | 162/185（87.6%） | 107/185（57.8%） | ✗ |

⇒ **没有任何一档出现"一侧过、一侧不过"的跨时间不可重复。**

### 3.4 DEFF 诊断（B 层）—— **[实测] 只报数，不称认证**

| U | 可估时段数 | `DEFF_ind` | `D_use` | 筛选结果 |
|---|---|---|---|---|
| 50 | **0/2** | **不可估（恒零序列）** | 2.707 | 通过（依赖假设） |
| 60 | **0/2** | **不可估（恒零序列）** | 2.707 | 通过（依赖假设） |
| 70 | 1/2 | 1.000 | 2.707 | 未通过 |
| 80 | 2/2 | 1.753 | 2.707 | 未通过 |
| 90 | 2/2 | 2.096 | 2.707 | 点估计已超 |

**必须带着的三条限定：**

1. **U50/U60 的 DEFF 不可估**：370 窗里指示量全为 0，方差为 0 ⇒ 自相关无定义。
   它们的 A 层通过**完全依赖 `D_assume=2.707`**，不是实测到的 DEFF。
2. **估得低于 2.707 不等于证明了真实 DEFF ≤ 2.707**。本轮不对任何 U 宣称"已认证"。
3. **U70 只有 1/2 时段可估**（a 段恒零），中位只来自单一时段，是最软的一个数。

> 本轮五个 `D_use` 全部等于 2.707（三个可估 DEFF 都低于它），
> 所以 `n_eff` 五档相同（136.68）；筛选差异**全部来自 k**，不来自 DEFF。

### 3.5 TLS 约束量分布 —— **[实测]**

| U | n | 中位 | p90 | p95 | max | 越限 |
|---|---|---|---|---|---|---|
| 50 | 370 | 40.29 | 51.89 | 54.42 | 70.83 | 0 |
| 60 | 370 | 46.96 | 61.23 | 65.93 | 76.18 | 0 |
| 70 | 370 | 52.51 | 67.57 | 73.39 | 109.28 | 1 |
| 80 | 370 | 65.50 | 84.97 | 92.35 | 139.23 | 5 |
| 90 | 370 | 117.89 | 185.19 | 205.68 | 389.63 | 269 |

- 中位数随 U **严格单调**（40.3 → 47.0 → 52.5 → 65.5 → 117.9）。
  **[推论]** 这是本批数据内部一致性最强的旁证：负载越高、时延越大，没有"标错档位/接错探针"的迹象。
- **U90 的悬崖**：中位已越 100 ms 本身，越限率必然过半。
  U80→U90 中位跳了 52 ms，而 U50→U80 总共只跳 25 ms。
  **[未答]** 这是曲线拐点还是队列饱和，本数据无法区分。

## 5. 结论

### A 层（条件性工程筛选，对外主产出）

> **U50 与 U60 在假设 DEFF ≤ 2.707 的条件下通过筛选**（k=0/370，单侧上界 **1.941%** < 2%）。
> **U70、U80 尚无法认证**（点估计 0.27% / 1.35% 都低于 2%，但上界 2.44% / 4.16% 未过线；
> **不等于不安全**）。
> **U90 点估计未达标**（72.70%）。

⇒ **条件性候选负载名单：U ∈ {50, 60}。**

### B 层（DEFF 可估性）

> U50/U60 的 DEFF **不可估**，其通过完全依赖 `D_assume=2.707`；
> U70=1.000（仅 1/2 时段）、U80=1.753、U90=2.096，均低于假设值，
> **但低于假设值不构成认证**。

### 严格认证层

> **本轮不宣称完成。五档一律记「尚无法认证」。**

### 写死的边界

- 不把「尚无法认证」写成「不安全」；
- 不把「实测率 <2%」写成「证明了真实概率 <2%」；
- 不给「无条件可用于训练」的结论 —— A 层措辞必须带定语"在假设 DEFF≤2.707 的条件下"。
