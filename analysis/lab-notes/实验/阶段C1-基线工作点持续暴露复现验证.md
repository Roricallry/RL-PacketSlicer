# 阶段 C1：基线工作点的持续暴露复现验证

> **一句话**：在新的两个夜晚，把两个**固定工作点**（U50/P=1.0、U60/P=0.5）**长时间恒定保持**，
> 检验此前 4B 的越限率与典型时延/熵增能否复现，以及 session 内有没有时间漂移。

**它不验证控制器**。C1 每个 session 内 P 固定、U 固定，**不根据新观测动态改变动作**，
因此**不能作为闭环控制器有效性的证据**（GPT Round 30 v3 明确要求改此措辞）。

---

## 1. 为什么需要 C1

### 1.1 起点：4B 给出了第一个非空的可行集

Round 29（4B）在逐窗随机 P 的采集下，得到条件性候选集合：

| 负载 | 条件性可行集 | 最大候选 P |
|---|---|---|
| U50 | P ∈ {0, 0.5, 1.0}（全部 0 越限） | **1.0** |
| U60 | P ∈ {0, 0.5}（全部 0 越限） | **0.5** |
| U60 | P=1.0 **尚无法认证**（k=3/370，上界 3.338%） | — |

全部判定都带定语「**在假设 DEFF ≤ 2.707 的条件下**」，**不是严格安全认证**。

### 1.2 4B 的结构性缺口：从未测过「长时间保持同一 P」

4B 的 P 是**逐窗随机**的，同一 P 的连续段通常只有 ~3 窗。
而基线策略的真实运行方式是**在固定负载下长时间保持一个 P**。
**持续暴露与随机暴露不是同一种运行状态**，这是 C1 的唯一新信息，也是它存在的理由。

### 1.3 装置事实（决定了设计形状）

1. **U 不是控制器的动作**。U 由负载服务设定；换 U 必然伴随 iperf3 停→起，
   不是控制器切换 ⇒ U 切换暂态**移出本轮**（GPT Q2 同意）。
2. **冻结采集器能在 session 内做任意 P 序列**（只读 schedule），P 恒定不需要改采集器。
3. **U 本身几乎无噪声**（实测中位 U50 52.44%、U60 62.92%，相隔 10.4 pp，噪声 ~0.7 pp），
   所以「测量 U 再决策」在当前档位间没有可改善空间 ⇒ C3（状态特征增量价值）**暂缓**。

## 2. 设计矩阵

| 项 | 值 |
|---|---|
| 工作点 | **U50 / P=1.0**、**U60 / P=0.5**（各 1 个） |
| session | **4 个 × 370 窗**（每格 2 个 session） |
| 时段 | **2 个新夜晚**，每夜 2 个 session，**间隔 ≥1 天**、同钟点 22:00 起 |
| 顺序 | 夜 A：U50/P1 → U60/P0.5；夜 B：**U60/P0.5 → U50/P1**（反序） |
| 总窗数 | **1480 窗 ≈ 13.4 h**（370 × 32.6 s ≈ 3.35 h/session） |
| 每格可用窗 | **740** |
| P 序列 | **整段恒定**，不是随机 |

冻结的 schedule 版本为 `stagec1-constp-v1`，哈希 `5e37c7d9…8f237`。

> **为什么保持同钟点**：4B 的对照是同钟点采集；换钟点会把 time-of-day 效应混进复现差。
> **为什么不写「间隔 7 天」**：没有证据表明 7 天是独立重复的门槛；报告中只写实际日期与起止时间。

---

## 3. 为什么是 370 × 2 = 740，而不是 370

这是整份设计**最关键的一条算术理由**：现有 §9 条件性筛选在 n=370 时**没有容错余量**。

| n | k=0 | k=1 | k=2 | k=3 | k=4 | k=5 |
|---|---|---|---|---|---|---|
| **370** | 1.941% ✓ | **2.442% ✗** | 2.902% ✗ | 3.338% ✗ | 3.756% ✗ | — |
| **740** | 0.980% ✓ | 1.233% ✓ | 1.466% ✓ | 1.686% ✓ | **1.898% ✓** | 2.103% ✗ |

（D = 2.707，z = 1.6448536，单侧 95%；✓ = Wilson 上界 < 2%）

- 在 **370 窗**上，**1 个越限就把判定从「通过」翻成「无法认证」**。
  若真实比例是 0.2%，370 窗的期望事件数 0.74 ⇒ **约 52% 的概率「复现失败」，即使系统一点没变**。
  这样的复现实验**没有判别力**。
- 在 **740 窗**上容错到 **k=4**。真实比例 0.2% ⇒ 期望 1.48 个事件，通过概率约 98%；
  真实比例 0.8% ⇒ 期望 5.9 个事件，大概率失败。**这才有判别力。**

> 注意：上表的 k≤4 只是 **D=2.707 时的规划值**。正式分析必须用实测 DEFF 算上界，
> 实测 DEFF 更高时允许的 k 更小。

## 4. 要回答的三个问题（R1 / R2 / R3）

### R1 安全层（主）——越限率能否复现

判定对象：**TLS 单窗 > 100 ms 的比例**。
口径：`p̂ = k/n`，`n_eff = n / D_use`，`D_use = max(2.707, DEFF_obs)`，Wilson 单侧 95% 上界。

**样本门槛**（逐时段，GPT Q1 硬要求）：

$$
n_a \ge 360,\quad n_b \ge 360,\quad n_a + n_b \ge 720
$$

**四层判定（顺序执行，不可合并）**：

| 顺序 | 条件 | 输出 |
|---|---|---|
| 1 | 任一时段 <360 或合计 <720 | **尚无法完成复现判定**（不记失败） |
| 2 | 样本够，`k/n ≥ 2%` | **点估计未达标** |
| 3 | 样本够，`k/n < 2%`，但上界 ≥2% | **尚无法认证**（≠ 不安全） |
| 4 | 样本够，`k/n < 2%`，上界 <2% | **条件性通过复现**（带定语「假设 DEFF≤2.707」） |

> **第 2 层与第 3 层不能合并**：「点估计 <2% 但上界过线」既不等于「未复现」，更不等于「不安全」。

**DEFF 口径（必须分开）**：

- 安全层的 `DEFF_obs` 从**二值越限序列** $Y_i=\mathbf 1(\mathrm{TLS}_i>100\text{ ms})$ 估计，
  **逐 session** 估、**不跨夜拼接**。
- 恒零或零方差序列 ⇒ **DEFF 不可估**，不是 DEFF=0，也**不得默认 DEFF=1**。
  可估 session 的处理：多个取中位；只有一个则照实用（报告「可估数 = 1/2」）；全部不可估用 `D_assume=2.707`。
- 连续 TLS 序列的 DEFF（实测 0.83–2.27）**只用于描述时延相关性**，**不能**当作安全层的设计效应。

### R2 复现层——典型 TLS / ΔR 能否回到 4B 水平

| 判据 | 阈值 |
|---|---|
| TLS 中位差 | **≤ 10 ms** |
| ΔR 中位差 | **≤ 0.10 bit** |

**汇总口径（开采前冻结，GPT Q3 要求）**：
`(C1 两 session 中位的均值) − (4B 两 session 中位的均值)`，**等权**，不在数据到手后挑池化或某一段。

4B 预先登记的参照值：

| 工作点 | TLS 中位（4B a / b） | 等权参照 | ΔR 中位（4B a / b） | 等权参照 |
|---|---|---|---|---|
| U50 / P1.0 | 60.48 / 61.09 ms | **60.79 ms** | 2.5866 / 2.5760 | **2.5813 bit** |
| U60 / P0.5 | 54.14 / 57.05 ms | **55.60 ms** | 2.2581 / 2.2855 | **2.2718 bit** |

> **10 ms 不是拍脑袋**：4A 与 4B 同名 P=0 格子的中位差实测最大 **6.3 ms**（U60a）⇒ 容差必须大于跨批次本底。
> 4B 逐窗 TLS 的 SD 为 7.8–8.9 ms；按 D=2.707 算 n=740 的中位 CI 约 ±1.3 ms ⇒ 10 ms 有约 7 倍余量。
> 但它只是**工程阈值**：只回答「水平是否大体回到同一档」，**不称统计等价**。

**不确定性**：移动块 bootstrap，块长 = **实际时间连续的 10 窗**（≈5.4 min），
两个批次用同一种时间块；4B 在块内保留原始 P 标签；**每个 session 各自重采样，绝不跨 session 拼接**。

### R3 持续层（诊断）——session 内有没有漂移

每个 session **前 1/3 vs 后 1/3** 的中位 TLS 差：

- 报告该差值；
- **> 5 ms ⇒ 标记「持续暴露下有漂移」**；
- **只标记，不单独否决**任何工作点。

另有 **R4 分时段**：夜 A vs 夜 B 各自 n / k / 中位，描述性分报，不替代 R1。

## 5. 闸门与执行完整性

| 闸门 | C1 中的用法 |
|---|---|
| E1（P=0 的 ΔR=0） | **不适用**（没有 P=0 窗） |
| E2（`realized_split_ratio` 带内） | P=0.5 ∈ [0.10, 0.90]；P=1.0 ∈ [0.95, 1.00]；逐窗、分母 = 计划窗数 |
| E3（序列 + 应用） | `p_requested` 必须**恒等于该 session 的 P**；`p_applied == p_requested` |
| **E4（新）负载稳定** | 每窗利用率相对 session 中位偏离 >10 pp 记一次告警；**报告计数，不剔除窗** |

**E2 与 E3 的边界必须分开**：

- **E2 异常**：报告并保留告警标记；在没有预先冻结整体阈值的前提下，
  **不因单个低分母窗口事后否决整个工作点**（4B 的 U50b idx29 分母为 1 就是例子）。
- **E3 异常 = 执行完整性问题**：立即暂停调查、单独记录；
  **不得降级成普通 E2 异常**；未经审查**不得**当作有效复现样本；
  **不自动补采**、**不改统计口径绕过**。

## 6. 什么算「没复现」

| 结论 | 条件 | 后续 |
|---|---|---|
| 尚无法完成复现判定 | 样本门槛不足 | **不判失败**；报告缺在哪一段；补采是单独决策 |
| 点估计未达标 | `k/n ≥ 2%` | 停止推进、报告；**不自动降 P** |
| 尚无法认证 | `k/n < 2%` 但上界 ≥2% | **≠ 不安全、≠ 未复现** |
| 条件性通过复现 | `k/n < 2%` 且上界 <2% | 带定语，**不称安全认证** |

R2 超出容差时写作 **「复现失败 → 先诊断」**，不直接归因于持续暴露。

**不算未复现、但必须记录**：R3 有漂移但水平在容差内；只有一夜偏差；
个别低样本窗（按 4B 规则保留、标记，只做敏感性）。

> **不做**「R1 失败就自动降到 P=0.5」。降档是策略决策，属于决策方，不属于分析。

## 7. 与 4B 的可比性边界

C1 与 4B 的**暴露机制不同**（持续恒定 vs 逐窗随机），所以差异**不能直接归因于「策略变了」**。
可能来源至少三类：

1. **机制**：持续暴露 vs 随机暴露；
2. **批次/日期**：4A 与 4B 同名 P=0 就差过 6.3 ms；
3. **time-of-day**：本设计保持同钟点，已尽量控制。

> 若 R2 没过：**先在同一新批次里补一个随机对照**（4B 式），再判断是机制还是批次。
> **不在同一批次里，不写「持续暴露导致」这种因果句。**

## 8. 后续阶段与边界

### C2：持续保持后的 P 阶跃（条件触发，第二波）

GPT 修改后的触发逻辑：

| 触发情形 | 动作 |
|---|---|
| **R2 没过** | **先诊断，不自动做 C2**；优先考虑同批次的随机 P 对照 |
| **R3 持续漂移（>5 ms）** | 可以触发 C2 |
| **明确要研究 P 阶跃** | 可单独触发，不必等 C1 出问题 |

若触发：固定 U50，2 个 session × 370 窗，5 块 × 74 窗交替 1.0/0.5，
**两个 session 起始块相反**；判据为阶跃后第 1–10 窗 vs 同块第 21–74 窗。

### C3：状态特征的增量价值——暂缓

> **当前动作集合、风险事件数量和已验证工作点，尚不足以让状态特征的增量决策价值
> 成为一个有足够统计支撑的主要研究问题。**

在现行候选集合内它**没有决策余量**：基线已取每个负载的最大条件 P，
「降 P」只会减少 ΔR 而不改善时延，「升 P」即 U60/P=1 而它尚未认证。
U60/P=1 在 4B 只有 **3 个越限窗 / 370**，连训练集都不够。

### 路线边界

- C1 **不是**开始 Contextual Bandit 离线实验的绝对前置条件，两条工作可以**并行**。
- 但 **C1 与离线实验都不能单独证明**最终闭环策略安全有效。
- **C1 完成前，不得把现有基线描述为「已通过持续运行复现的安全策略」。**
- **CSAC 不恢复、不调整训练配置。**
