**ai**: I'll open that note to see the context.## $W$ 是什么

$W$（严格写法 $W(F)$）在 [[待讨论]] 里出现的所有 $W$，都指同一个东西：**在观测到帧长序列 $F$ 的前提下，所有“自洽切分方案”的总数**，也就是自洽解空间的大小。

### 形式定义（见 [[repository/metric_theoretical_foundation]] 1.2 节）

给定帧长序列 $F=[f_1,\dots,f_m]$ 和合法报文长度集合 $S$（比如各类协议的报文长度），一个合法切分方案是一组下标 $1=i_0<i_1<\dots<i_k=m+1$，要求每段帧长之和都落在 $S$ 里：

$$\sum_{r=i_{j-1}}^{i_j-1} f_r \in S,\quad \forall j$$

满足这个条件的下标序列个数就是 $W(F)$。

### 它的物理含义

在“包边界不可见”的假设下，攻击者只看到一串帧长，他必须猜这些帧是怎么拼成原始报文的。$W$ 就是他能拼出来的**同样说得通的候选解个数**。然后取 $\log_2 W$ 换成比特，就是“锁定真实报文还差多少信息”（Hartley 熵上界，与 Serjantov–Danezis 的匿名集熵同构；若唯一可译则 $W=1$、熵为 0，对应 Sardinas–Patterson 的唯一可译性）。

度量本身再做归一化：$\log_2 W / n_{\text{packets}}$ 或 $\log_2 W / n_{\text{frames}}$，单位是 bit/包 或 bit/帧，因为 $W$ 随流长指数增长（$W\sim c^n$），不归一化就不收敛。

### 回到 [[待讨论]] 里那条结论

- $W \ge 1$ 是恒成立的（至少“原始切分”本身总是一个解）。
- 文档里反复出现的 $W \equiv 1$，意思是**在这个威胁模型下解空间退化成一个解**，歧义度归零：
  - 攻击者只看长度 → 分帧把 $W$ 抬起来，度量有意义；
  - 攻击者能字节级重组 → TLS 记录长度字段直接暴露，唯一自洽解就是原始切分，$W=1$，$\log_2 W/n = 0$，度量失效。

所以 $W$ 是度量的分子核心量（“歧义候选解个数”），$\log_2 W/n$ 是“每包/每帧平均还欠多少比特才唯一可译”。需要注意的一点（待讨论里第 2 条也提到了）：这里的“切分单位”实际上是 TLS 记录而非 TCP 包，所以 $S$ 应理解为 TLS 记录长度集合，而不是应用层报文长度集合。

**ai**: 不对，$W$ 不是“排列”（排序），而是“切分/分组”。具体说：

## 两种不同的组合

| | 排列（你说的“排序”） | 切分（$W$ 实际计算的） |
| :-- | :-- | :-- |
| 在做什么 | 把 $n$ 个报文重新排成不同顺序 | 把一串帧**划分成若干段**，每段当作一个报文 |
| 是否改变顺序 | 改变 | **完全不改变**，帧的顺序 $f_1,f_2,\dots,f_m$ 固定不动 |
| 个数 | $n!$ | 选若干个“切点”位置，最坏 $2^{m-1}$ 量级 |
| 受什么约束 | 无 | 每段和必须落在合法长度集合 $S$ 里 |

$W$ 的数学对象是：给定帧长序列 $F=[f_1,\dots,f_m]$，从 $m-1$ 个相邻间隙中选出若干个作为“报文边界”，使得**每一段连续帧的和都是合法报文长度**。满足这个条件的选法总数就是 $W$。所以它本质上是**对连续帧的分段方式数**，不是对报文的置换数，帧的时序完全保留。

## 为什么要用这个量

- 排列方案数为 $n!$（$n$ 是报文数），而 $W$ 是切分方案数；前者不依赖 $S$，后者由 $S$ 和帧长决定。
- 只统计分段组合，不统计排列，正好对应攻击者的真实任务：他看到的只是一个不可分辨的帧长序列，任务是**猜原始报文在哪里被切开**，而不是猜它们本来按什么顺序发送（已经由物理到达顺序给定了）。
- 这也是为什么 [[待讨论]] 里说：如果观测是全字节流，那么“哪处是真正的边界”被长度字段直接给出，只剩一种分段方式，$W=1$。这说明 $W$ 只关心分段，不关心重排。

## 一句话修正

> $W$ = 在给定帧长序列下，所有**满足“每段和 ∈ 合法长度集合 $S$”的连续分段方式**的个数。

不是“$n$ 个数据包的排序解个数”。

**ai**: 我先把 TLS 连续时延的定义，以及 U 与 ICMP 的作用，再仔细核对一遍。## 一、TLS 连续时延是什么

它并非某种特殊技术，只是**相对于二值变量的一种数据用法**。同一个 `tls_constraint` 字段（在 [[口径与术语]] 中定义：`br-lan` 被动抓包，把出站段 `seq+len` 与回来的 ACK 配对，RTT = 两时间戳之差，1.5×IQR 剔除后取均值）可以有两种用法：

| 用法 | 取值 | 出现在哪 |
| :-- | :-- | :-- |
| **连续量**（continuous） | 直接使用毫秒值，如 43.6 ms、64.55 ms、>1000 ms | 回归目标，MAE / R²；“TLS 连续量是否漂”（格 3 的参照用途） |
| **二值量**（binary） | $1\{\text{tls\_constraint} > 100\ \text{ms}\}$，即“越限 / 超时” | 控制器的约束代价、越限率 $p$、AUC |

所谓“TLS 连续时延预测”，就是**对下一个窗口的 `tls_constraint` 毫秒数值做回归**。G3 的结论（§3.4）是：这件事唯一可靠的预测因子是 **TLS 自己的上一窗值**（M2，10/10 折，效应量 9%）；加入 ICMP 后 MAE 从 19.02 升到 21.45 ms，只赢 2/10 折。

注意这个量本身有噪声：它是 TCP ACK RTT，不是应用层 RTT，会受延迟确认、重传、合并 ACK 的影响，单条样本噪声约 ±13–20 ms。因此“单窗差值”不能作为结论，只能观察簇或格这一级的漂移。

## 二、不能直接用 ICMP 替代 U 的四个理由

U 指 **139 节点 iperf3 施加的链路负载百分比**，是**实验者设定的环境条件**；ICMP 指**每窗 30 次 ping 后的均值**，是**被动测量结果**。两者在控制问题中的位置不同。

**1. U 是“因”，ICMP 是“果的另一条支路”**
U 是人为加上的负载，ICMP 是这种负载造成的若干后果之一。用 ICMP 替代 U，等于用结果推测原因：中间的映射关系会随环境变化，因为环境本身就随时间变化（§3.2：格内跨簇方差 29.8%）。同一 U 在不同时间的 ICMP 可以相差很大。

**2. 不是一一映射（多因一果）**
ICMP 时延还受网关 `.5` 自身状态、无线信道干扰、其他流量影响；U 则是**唯一可被实验者精确控制**的变量。U→ICMP 不是从单变量到单变量的映射，替代后无法区分“负载变了”和“信道条件变了”。

**3. U 是离散可控的，ICMP 是不可控观测量**
U 有固定档位（U60/U80/U90/U95…），可用于平衡设计、分层分析和方差分解（格间 33% 就是按 (U,P) 划分得到的）。ICMP 是连续噪声量，无法作为**实验设计的划分维度**。一旦失去 U，整个格-簇-窗三层结构就不存在了。

**4. 因果效应无法识别：ICMP 可能是动作依赖的观测**
这是最硬的一条（§3.5 的风险假设）：**如果分割动作 P 也会影响 ICMP**，那么 ICMP 就是**动作依赖**的状态，并非外生状态。此时把 ICMP 作为输入充当“环境”，等于把动作的一部分反馈塞回状态，会导致策略无法学习。这条目前标注为[待验证]，但它一旦成立，替代方案就彻底不可行；而 U 作为实验者设定量，天然外生。

---

## 三、ICMP 在控制循环中的合理用法

它不能替代 U，但可以作为**窗内扰动的观测或特征**，而且它确实有价值，只是价值体现在不同地方：

- **对“下一窗是否越限”（二值）有增量**：AUC 0.850 → 0.912；
- **对连续时延值没有稳定增量**：所以不能把 ICMP 当成 TLS 时延的预测输入；
- **最能解释的是格内跨簇漂移**（89%），这正好是“U、P 确定不了的那部分”。

可以这样概括：

> U 是**动作与环境的划分依据**（可控、外生、离散），ICMP 是**环境扰动的一条独立观测通道**（不可控、可能动作依赖、连续）。前者决定“我们在哪个格子里做实验”，后者只帮助解释“同一格子里的即时波动”。

如果你问的其实是“能不能用 ICMP 替代 U 作为 RL 的**状态输入**”，那答案是：**技术上可以塞进去，但会把外生变量换成可能的动作依赖变量**；而且 G3 连“ICMP 能否单独预测未来连续时延”都没能回答（§5 未答项 4），没有证据支持它承担这个角色。
